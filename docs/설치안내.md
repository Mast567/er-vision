# ER Vision 설치 안내

전부 브라우저에서 할 수 있다. 설치할 프로그램은 없다.

| 조각 | 어디에 | 역할 |
|---|---|---|
| 화면 | GitHub Pages (`https://<아이디>.github.io/er-vision/`) | 대시보드, 분석, 복기노트, 같이 한 사람들, 코칭 리포트, 닉네임 조회 |
| 데이터 창구 | Cloudflare Worker (`https://er-vision.<이름>.workers.dev`) | 게임 API 호출, 데이터 저장(D1), 자동 수집 |

화면은 공개 주소지만 비밀 코드 없이는 데이터가 나가지 않는다. 비밀 코드와 API 키는 저장소에 들어가지 않고 GitHub 비밀값과 Cloudflare에만 있다.

## 1. Cloudflare 준비 (한 번만)

1. dash.cloudflare.com 무료 가입. Workers & Pages에서 `workers.dev` 하위 주소 이름을 정한다(공개되니 실명은 피한다).
2. 오른쪽 위 프로필 → My Profile → API Tokens → Create Token → **Edit Cloudflare Workers** 템플릿 → 권한에 **Account / D1 / Edit** 추가 → 생성 → 토큰 복사(한 번만 보임).
3. 계정 ID: Workers & Pages 개요 오른쪽, 또는 대시보드 주소 `dash.cloudflare.com/` 뒤의 32자리.
4. GitHub 저장소 Settings → Secrets and variables → Actions → New repository secret 으로 4개 등록:
   `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`, `ER_API_KEY`(이터널 리턴 API 키), `SITE_TOKEN`(사이트 비밀 코드).

## 2. 배포

`worker/` 가 바뀌어 main에 올라오면 자동으로 배포된다. 수동으로 돌리려면 저장소 Actions → Deploy worker → Run workflow.
처음 배포 때 데이터베이스(`er-vision`)를 만들고 테이블을 적용한 뒤 Worker를 올리고 비밀값을 등록한다.
성공하면 '배포' 단계 로그에 `https://er-vision.<이름>.workers.dev` 주소가 나온다.

## 2-1. 디스코드 로그인 설정 (v0.3부터, 한 번만)

v0.3부터는 사람마다 디스코드로 로그인하고, 복기노트·코칭 리포트·경기 기록이 계정마다 따로 저장된다.

1. https://discord.com/developers/applications 에 로그인 → [New Application] → 이름 `ER Vision` → 약관 체크 → [Create].
2. 왼쪽 메뉴 [OAuth2] → Client ID 옆 [Copy]로 복사해 둔다. Client Secret 옆 [Reset Secret]을 눌러 나온 값도 복사해 둔다(다시 보여주지 않는다).
3. 같은 화면 Redirects → [Add Redirect] → `https://<Worker 주소>/auth/callback` 입력 → 아래 [Save Changes].
4. GitHub 저장소 → Settings → Secrets and variables → Actions → [New repository secret]으로 두 개를 추가한다.
   - `DISCORD_CLIENT_ID` = 2번의 Client ID
   - `DISCORD_CLIENT_SECRET` = 2번의 Client Secret
5. Actions 탭 → Deploy worker → [Run workflow]로 다시 배포한다.
6. 사이트에서 [디스코드로 로그인] → 설정 → [기존 데이터 가져오기]에 예전 비밀 코드(SITE_TOKEN)를 넣으면 v0.2까지의 데이터가 내 계정으로 복사되고, 그 계정이 관리자가 된다.

다른 사람에게 알려 줄 때는 사이트 주소 끝에 `#api=<Worker 주소>`를 붙인 링크를 주면 서버 주소를 따로 입력하지 않아도 된다. 매번 붙이기 싫으면 `js/config.js`의 `apiUrl`에 Worker 주소를 적는다(저장소가 공개라면 그 주소도 공개된다).

되돌리기: v0.3은 새 테이블만 추가하고 예전 테이블을 지우지 않는다. v0.21 커밋으로 되돌리면 예전 데이터로 그대로 돌아간다. 다만 v0.3에서 새로 쓴 노트는 v0.21 화면에 보이지 않는다.

## 3. 데이터 옮기기 (구글 시트를 쓰던 경우)

1. 사이트를 지금처럼 시트(Apps Script)에 연결된 상태로 연다.
2. 설정 → 데이터 창구 옮기기 → 새 Worker 주소와 비밀 코드(SITE_TOKEN) → **[지금 연결에서 옮기기]**.
3. 완료되면 그 브라우저는 새 창구를 쓴다. 다른 기기에서는 처음 화면에서 새 주소와 비밀 코드를 넣는다.
4. 시트 메뉴 [ER 복기] → [자동 갱신 끄기]. 시트는 지우지 말고 백업으로 둔다.

시트 연결이 안 될 때는 설정 → [백업 내려받기]로 만든 파일을 [백업 파일에서 옮기기]로 넣어도 된다.
팀원 기록 없이 옮겨지면 새 창구가 경기 상세를 다시 받아 채운다(사이트를 열어 두면 약 7분).

## 처음부터 Worker로 시작하는 경우

1~2를 한 뒤 사이트 첫 화면에 Worker 주소와 비밀 코드를 넣고, 설정 → 내 닉네임 저장 → [지금 갱신].

## Worker 쪽에서 자주 막히는 것

| 증상 | 원인과 조치 |
|---|---|
| Actions가 빨간 X, "비밀값 ... 가 없습니다" | 1-4의 비밀값 이름이 다르다. 대소문자까지 같게. |
| "Authentication error" | 토큰 권한 부족. 템플릿 + Account / D1 / Edit 인지 확인하고 토큰을 새로 만들어 비밀값을 바꾼다. |
| "D1 데이터베이스 ID를 찾지 못했습니다" | 위와 같음 (D1 권한). |
| "You need to register a workers.dev subdomain" | Cloudflare → Workers & Pages에 처음 들어가 하위 주소 이름을 정한 뒤 Actions를 다시 실행. |
| 사이트에서 "비밀 코드가 틀렸습니다" | 사이트에 넣은 코드와 GitHub의 SITE_TOKEN이 다르다. |
| 오류 1102 / "exceeded CPU" | 한 번에 처리하는 양이 많다. `worker/wrangler.toml`의 `DETAIL_PER_RUN`·`LIST_PAGES_PER_RUN`을 줄여 올리면 자동 재배포된다. |

## 비용

무료 플랜으로 충분하다(결제 수단 없음, 한도를 넘으면 그날 멈출 뿐 청구되지 않음). 공개 후 처음 보는 닉네임의 정밀 분석이 하루 150건을 넘기 시작하면 월 $5 유료 플랜을 검토한다.

# (이전) 구글 시트 + Apps Script 데이터 창구

## 1. 데이터 창구 (Apps Script) 설치

1. 구글 시트 "이터널 리턴 랭크 복기 노트"를 연다.
2. [확장 프로그램] → [Apps Script]. 편집기가 새 탭에 열린다.
3. 편집기 안의 기존 코드를 모두 지우고(Ctrl+A, Delete), 저장소의 `apps-script/Code.gs` 내용을 전부 붙여 넣는다(GitHub에서 파일을 열고 Raw 버튼 → Ctrl+A, Ctrl+C). 저장(Ctrl+S).
4. 시트 탭으로 돌아가 새로고침(F5). 상단 메뉴에 [ER 복기]가 생긴다.
5. [ER 복기] 메뉴를 위에서부터 한 번씩 실행한다.
   - 1. API 키 설정 (처음 한 번은 권한 승인 창이 뜬다 → 계정 선택 → [고급] → [안전하지 않은 페이지로 이동] → [허용])
   - 5. 사이트 비밀 코드 설정 (내가 정하는 비밀번호. 사이트 로그인에 쓴다)
   - 6. 사이트용 탭 만들기 (작업 / 캐시유저 / 캐시경기 탭이 생긴다)
   - 3. 캐릭터·지역 한글명 갱신
   - 4. 매일 자동 갱신 켜기
6. (기능 파일) 편집기 왼쪽 "파일" 옆 [+] → [스크립트] → 이름을 `Companions` 로 입력 → 저장소의 `apps-script/Companions.gs` 내용을 붙여 넣고 저장. 이 파일이 "같이 한 사람들" 기능의 데이터 쪽이다. 기능을 빼고 싶으면 이 파일만 삭제하면 된다.
7. 웹 앱으로 배포한다.
   - Apps Script 편집기 오른쪽 위 [배포] → [새 배포]
   - 왼쪽 톱니(유형 선택) → [웹 앱]
   - 설명: 아무거나 / 다음 사용자 인증 정보로 실행: **나** / 액세스 권한이 있는 사용자: **모든 사용자**
   - [배포] → 권한 승인 → "웹 앱 URL"(…/exec 로 끝남)을 복사해 둔다.

"모든 사용자"로 열어도 비밀 코드가 맞아야만 응답하므로 데이터는 보호된다.

## 화면 (GitHub Pages)

저장소 Settings → Pages → Build and deployment → Source: **Deploy from a branch**, Branch: **main** / **(root)** → Save. 1~2분 뒤 `https://<아이디>.github.io/er-vision/` 가 열린다.

## 3. 처음 접속

사이트를 열면 "데이터 창구 주소"와 "비밀 코드"를 묻는다. 1-6에서 복사한 웹 앱 URL과 1-5에서 정한 비밀 코드를 넣고 [연결]. 이 두 값은 그 브라우저에만 저장되고, 다른 PC에서는 다시 입력하면 된다.

## 코드를 고친 뒤에는

- 화면(`index.html`, `js/`, `css/`)은 저장소에 올리면 1~2분 안에 반영된다.
- 데이터 창구(`apps-script/Code.gs`, `apps-script/Companions.gs`)는 편집기에 다시 붙여 넣고 저장한 뒤, [배포] → [배포 관리] → 연필(편집) → 버전: **새 버전** → [배포]. 이걸 안 하면 옛 코드가 계속 돈다. URL은 바뀌지 않는다.

## 자주 막히는 것

| 증상 | 원인과 조치 |
|---|---|
| 연결 시 "비밀 코드가 설정되지 않았습니다" | 메뉴 5번을 실행하지 않았다. |
| 연결 시 "비밀 코드가 틀렸습니다" | 메뉴 5번에서 정한 값과 다르다. 다시 설정해도 된다. |
| 연결 시 아무 반응 없이 실패 | 웹 앱 URL이 `/exec`로 끝나는지, 액세스 권한이 "모든 사용자"인지 확인. `/dev`로 끝나는 주소는 안 된다. |
| 정밀 분석이 "대기 중"에서 멈춤 | Apps Script 편집기 왼쪽 [트리거] 메뉴에 `processJobs`가 있는지 확인. 없으면 정밀 분석을 한 번 더 누른다. [실행] 메뉴에서 오류 로그도 볼 수 있다. |
| 일반·코발트 경기가 안 보임 | 모드 열(AR)이 생기기 전 버전으로 수집된 기록은 전부 랭크로 취급된다. 새 버전 배포 후 [지금 갱신]부터 세 모드가 모두 저장된다. 화면 위 "모드" 선택기에서 고른다. |
| "지금 갱신"이 2분 넘게 걸림 | 한 번에 최대 60판만 가져온다. 끝나면 "n판 남음" 메시지가 뜨고, 한 번 더 누르면 이어서 가져온다. |
| 한글명 갱신에서 "키를 찾지 못했습니다" | 번역 파일 형식이 예상과 다르다. 알림에 나온 키 예시를 Claude에게 알려주면 고친다. |

## 기능 추가 방식 (격리 구조)

핵심 파일(`js/app.js`, `worker/src/ext.js`)은 고리만 제공하고, 각 기능은 자기 파일에서 완결된다.

| 기능 | 화면 파일 | 데이터 창구 파일 | 켜고 끄기 |
|---|---|---|---|
| 같이 한 사람들 | `js/features/companions.js` | `apps-script/Companions.gs` | index.html의 script 한 줄 / Apps Script 파일 삭제 |

새 기능은 `js/features/<이름>.js`에서 `ERV.registerView({...})`로 화면을 등록하고, 데이터가 필요하면 `apps-script/<이름>.gs`에서 `EXT.actions`, `EXT.onOwnerGameDetail`, `EXT.bootstrap`, `EXT.ensureSheets`에 함수를 등록한다.

## 로컬에서 화면만 확인하고 싶을 때 (선택, 개발용)

`tools/mock_server.py`는 API 없이 가짜 데이터로 화면을 띄우는 개발용 서버다. 실제 사용에는 필요 없다.
