# ER Vision

이터널 리턴 랭크 복기 사이트. 경기 기록을 자동으로 모으고, 어디서 탈락하는지 분석하고, 리플레이를 보며 복기노트를 쓰고, 코칭 리포트를 읽는다.

- 화면: 이 저장소 (GitHub Pages)
- 데이터 창구: Cloudflare Workers + D1 (`worker/`), main에 올리면 GitHub Actions가 자동 배포 (v0.2부터)
- 계정: 디스코드 로그인, 복기노트·리포트·경기 기록은 계정마다 따로 저장되고 본인만 본다. 노트는 판별로 공유 링크를 만들 수 있다 (v0.3부터)
- 이전 데이터 창구: 구글 시트 + Apps Script (`apps-script/`), 옮긴 뒤에는 백업으로만 둔다
- 설치: [`docs/설치안내.md`](docs/설치안내.md)

## 기능

| 화면 | 내용 |
|---|---|
| 대시보드 | 모드(랭크/일반/코발트/전체)·시즌 선택, 핵심 지표(최근 10판 vs 이전 30판 비교), 주차별 등수, RP 추이, 과거 시즌 요약, 최근 경기. 코발트는 승률·K/D·분당 피해 중심 |
| 분석 | 생존 구간별 탈락 지점, 데스 단계 분포, 근접 vs 원거리, 캐릭터별, 시작 지역별, 세션 피로(하루 n판째·시간대), 팀 구성 대비 성적, 킬러 캐릭터, 복기 태그 빈도 |
| 복기노트 | 경기 선택 → 결정적 순간, 상황, 실수 태그 3개, 잘한 점, 실천 과제 1개, 교훈, 자유 서술. 후반 포지셔닝 체크 질문 7개. 판별 공유 링크(닉네임 없이 그 노트만 보임, 언제든 끄기) |
| 같이 한 사람들 | 자주 함께한 트리오·사람별로 '함께할 때 잘 되는 것'(캐릭터·사거리·조합)과 상대 기준 칭호(정점 트리오, 폭주기관차…), 하이라이트. 본인 전용 |
| 코칭 리포트 | 시트의 코칭리포트 탭을 읽어 표시 |
| 닉네임 조회 | 최근 기록 분석(약 50판, 즉시) / 정밀 분석(90일 전체 + 경기 상세, 처음은 수 분, 이후 증분·10분 쿨다운). 한 사람당 하루 최근 기록 40회·새 정밀 분석 5회 |
| 설정 | 내 게임 닉네임, 지금 갱신, 기존 데이터 가져오기(v0.2 데이터 → 내 계정), 백업 내려받기·불러오기, 개인정보 안내, 로그아웃, 계정 삭제 |

## 모드

| 모드 | API 코드 | 저장 | 분석 |
|---|---|---|---|
| 랭크 | matchingMode 3 | 내 경기 + 닉네임 조회 | 등수·단계별 사망·RP 전부 |
| 일반 | 2 | 내 경기만 | 랭크와 같되 RP 없음 |
| 코발트 | 6 | 내 경기만 | 승률·K/D·피해·팀 킬 (4대4, 팀원 3명) |

일반·코발트는 API가 시즌을 0으로 주므로 경기 날짜로 시즌을 붙인다. 코칭 리포트는 랭크 기준으로 쓴다.

알려진 한계: API는 플레이어 고유 번호를 주지 않아 팀원을 닉네임으로만 구분한다. 닉네임을 바꾼 사람은 '같이 한 사람들'에서 두 사람으로 나뉜다.

## 데이터 흐름

```
이터널 리턴 Open API ──(초당 1회)──> Cloudflare Worker ──> D1 데이터베이스
                                          ▲      ▲
GitHub Pages 화면 ──(비밀 코드 포함 요청)──┘      └── 1분마다 cron: 정밀 분석 대기열, 내 경기 자동 수집(6시간마다), 메타 갱신(하루 1번)
```

무료 플랜은 실행 1회당 CPU 10ms라서 경기 상세(한 판에 약 190KB)는 필요한 네 칸만 뽑아 쓰고, 한 번에 5판씩 나눠 처리한다. 사이트가 열려 있으면 브라우저가 연달아 요청해서 초당 1판 속도를 내고, 닫혀 있으면 cron이 1분에 5판씩 이어 간다. 처리량은 `worker/wrangler.toml`의 `DETAIL_PER_RUN`, `LIST_PAGES_PER_RUN`으로 조절한다.

## 구조

```
index.html          화면 뼈대
css/style.css       스타일 (다크, PC 우선)
js/api.js           데이터 창구 호출
js/analysis.js      경기 배열 → 지표 (내 경기와 조회 경기가 공유)
js/app.js           화면 로직 (해시 라우팅, 기능 등록 창구 ERV)
js/features/*.js    기능 파일 (하나씩 격리, index.html 한 줄로 켜고 끔)
js/vendor/chart.umd.js  Chart.js 4.4.1 (MIT)
worker/src/index.js        데이터 창구 핵심 (Cloudflare Worker, 확장 고리 ext)
worker/src/features/*.js   기능별 데이터 창구 파일
worker/migrations/*.sql    D1 테이블 구조
.github/workflows/deploy-worker.yml  자동 배포
apps-script/*.gs           이전 데이터 창구 (구글 시트)
tools/mock_server.py 개발용 가짜 데이터 창구 (Apps Script 흉내)
tools/mock_er_api.py 개발용 가짜 게임 API (Worker 로컬 시험용)
```

## 버전

| 변화 | 번호 | 예 |
|---|---|---|
| 작은 수정 | 끝자리 +1 | v0.16 → v0.17 … v0.19 → v0.1.10 → v0.1.11 |
| 큰 기능 변화 | 0.x 단위 +1 | v0.19 → v0.2 → v0.21 |
| 정식 공개 | 정수 | v1 |

사이트(`js/app.js`)와 데이터 창구(`apps-script/Code.gs`)의 VERSION은 같은 번호를 쓰고, 설정 화면에서 볼 수 있다. git 태그도 같은 이름으로 단다.
