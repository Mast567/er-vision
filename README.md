# ER Vision

이터널 리턴 랭크 복기 사이트. 경기 기록을 자동으로 모으고, 어디서 탈락하는지 분석하고, 리플레이를 보며 복기노트를 쓰고, 코칭 리포트를 읽는다.

- 화면: 이 저장소 (GitHub Pages)
- 데이터: 구글 시트 + Apps Script 웹 앱 (`apps-script/Code.gs`)
- 설치: [`docs/설치안내.md`](docs/설치안내.md)

## 기능

| 화면 | 내용 |
|---|---|
| 대시보드 | 모드(랭크/일반/코발트/전체)·시즌 선택, 핵심 지표(최근 10판 vs 이전 30판 비교), 주차별 등수, RP 추이, 과거 시즌 요약, 최근 경기. 코발트는 승률·K/D·분당 피해 중심 |
| 분석 | 생존 구간별 탈락 지점, 데스 단계 분포, 근접 vs 원거리, 캐릭터별, 시작 지역별, 세션 피로(하루 n판째·시간대), 팀 구성 대비 성적, 킬러 캐릭터, 복기 태그 빈도 |
| 복기노트 | 경기 선택 → 결정적 순간, 상황, 실수 태그 3개, 잘한 점, 실천 과제 1개, 교훈, 자유 서술. 후반 포지셔닝 체크 질문 7개 |
| 같이 한 사람들 | 자주 함께한 트리오·사람별로 '함께할 때 잘 되는 것'(캐릭터·사거리·조합)과 상대 기준 칭호(정점 트리오, 폭주기관차…), 하이라이트. 본인 전용 |
| 코칭 리포트 | 시트의 코칭리포트 탭을 읽어 표시 |
| 닉네임 조회 | 최근 기록 분석(약 50판, 즉시) / 정밀 분석(90일 전체 + 경기 상세, 처음은 수 분, 이후 증분·10분 쿨다운) |
| 설정 | 지금 갱신, 다시 불러오기, 연결 해제 |

## 모드

| 모드 | API 코드 | 저장 | 분석 |
|---|---|---|---|
| 랭크 | matchingMode 3 | 내 경기 + 닉네임 조회 | 등수·단계별 사망·RP 전부 |
| 일반 | 2 | 내 경기만 | 랭크와 같되 RP 없음 |
| 코발트 | 6 | 내 경기만 | 승률·K/D·피해·팀 킬 (4대4, 팀원 3명) |

일반·코발트는 API가 시즌을 0으로 주므로 경기 날짜로 시즌을 붙인다. 코칭 리포트는 랭크 기준으로 쓴다.

알려진 한계: API는 플레이어 고유 번호를 주지 않아 팀원을 닉네임으로만 구분한다. 닉네임을 바꾼 사람은 '같이 한 사람들'에서 두 사람으로 나뉜다.

## 데이터 흐름

```
이터널 리턴 Open API ──(초당 1회)──> Apps Script ──> 구글 시트(경기기록·복기노트·캐시)
                                          ▲
GitHub Pages 화면 ──(비밀 코드 포함 요청)──┘
```

## 구조

```
index.html          화면 뼈대
css/style.css       스타일 (다크, PC 우선)
js/api.js           데이터 창구 호출
js/analysis.js      경기 배열 → 지표 (내 경기와 조회 경기가 공유)
js/app.js           화면 로직 (해시 라우팅, 기능 등록 창구 ERV)
js/features/*.js    기능 파일 (하나씩 격리, index.html 한 줄로 켜고 끔)
js/vendor/chart.umd.js  Chart.js 4.4.1 (MIT)
apps-script/Code.gs 데이터 창구 핵심 + 시트 메뉴 (확장 고리 EXT)
apps-script/*.gs    기능별 데이터 창구 파일
tools/mock_server.py 개발용 가짜 데이터 서버
```

## 버전

| 변화 | 번호 | 예 |
|---|---|---|
| 작은 수정 | 끝자리 +1 | v0.16 → v0.17 |
| 큰 기능 변화 | 0.x 단위 +1 | v0.19 → v0.2 → v0.21 |
| 정식 공개 | 정수 | v1 |

사이트(`js/app.js`)와 데이터 창구(`apps-script/Code.gs`)의 VERSION은 같은 번호를 쓰고, 설정 화면에서 볼 수 있다. git 태그도 같은 이름으로 단다.
